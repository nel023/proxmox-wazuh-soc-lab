# SSH Brute Force Detection – Windows Endpoint

## Use Case Overview
This detection use case documents how Wazuh identifies repeated failed SSH authentication attempts against a Windows 10 endpoint. The objective is to validate detection visibility, identify logging limitations, and assess how a SOC analyst would triage the alert.

---

## Log Source and Telemetry
- **Endpoint:** Windows 10  
- **Log Source:** Windows Security Event Log  
- **Event ID:** 4625 (Failed logon)  
- **Service:** Windows OpenSSH  
- **Collection Method:** Wazuh agent (Windows)

---

## Detection Logic
Wazuh detects this activity by correlating multiple failed authentication events within a short time window. Repeated Event ID 4625 entries associated with SSH activity trigger a brute-force alert.

The detection focuses on **behavioral patterns** (repeated failures) rather than a single authentication event.

---

## Alert Observations
The following fields were consistently present in the alert:
- Timestamp
- Agent name (Windows endpoint)
- Event ID (4625)
- Logon failure reason

The following fields were **not populated**:
- Source IP address
- Attacker hostname

---

## Identified Limitation
During analysis, failed SSH authentication events generated by Windows OpenSSH did not include source network address or hostname information in the Windows Security logs. As a result, Wazuh alerts lacked attacker attribution fields.

This limitation is attributed to **Windows OpenSSH and Windows Security Auditing behavior** during certain failed SSH logons. Wazuh cannot enrich attacker details that are not present in the original event data.

---

## Validation Method
The attack source was validated through lab context and timing correlation:
- SSH login attempts originated from the Kali VM
- Failed authentication timestamps aligned with Wazuh alerts
- Network topology confirmed the attacker path

---

## SOC Triage Considerations
An analyst reviewing this alert should:
- Confirm the frequency and time span of failures
- Identify the targeted account
- Check for subsequent successful logons
- Review recent authentication activity on the host

---

## Improvement Opportunities
- Collect Windows OpenSSH text logs for better attribution
- Correlate Windows Firewall logs to capture source IP data
- Enhance enrichment through multi-log correlation

---

## Summary
Wazuh successfully detected repeated failed SSH authentication attempts on a Windows endpoint. While attacker attribution was limited due to log source constraints, the alert provided sufficient evidence for identification and escalation within a SOC workflow.
